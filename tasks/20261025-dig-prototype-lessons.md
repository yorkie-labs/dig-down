## 2026-10-26 브라우저 검증 시 입력 오염
- 패턴: 자동화 도구로 키를 많이 보낸 뒤 "입력 없이 게임이 진행됨"을 버그로 의심했으나, 실제로는
  남은 키 이벤트/사용자 직접 플레이였음.
- 규칙: 상태가 이상하면 코드 수정 전에 keydown/keyup 로그를 찍어 입력 출처부터 확인한다.
  사용자가 같은 탭을 쓰고 있을 수 있으니, 검증 후에는 탭을 새로고침/조작하지 않는다.

## 2026-10-26 확인 안 된 수치를 원작 값처럼 말함
- 패턴: "9칸 폭(원작 비율)"처럼 검증하지 않은 값을 원작 근거가 있는 것처럼 설명했고, 사용자가 "원작과 동일한가?"라고 물음.
- 규칙: 원작/레퍼런스 수치를 말할 때는 출처별로 "확인됨 / 팬 자료 / 우리 선택"을 표시한다.
  코드 상수 주석에도 출처나 "우리 선택"을 적는다.

## 2026-10-27 레퍼런스를 도구 목록만 보고 해석함
- 패턴: 트윗의 "Blender + Tripo for 3D models"를 보고 캐릭터까지 3D로 만듦. 실제 게임은 캐릭터가 2D 스프라이트였음.
- 규칙: 레퍼런스를 따라 할 때는 설명문이 아니라 결과물(게임 화면)을 먼저 직접 확인하고, 어떤 요소에 어떤 도구를 썼는지 매핑한다.

## 2026-10-28 사라짐 연출 취향
- 사용자: "쪼그라드는 느낌보다 부서지는 느낌이 더 좋아".
- 규칙: 블록 파괴 연출은 축소/페이드보다 물리적으로 부서지는 조각(쪼개짐·튐·회전·중력)을 기본으로. 같은 잉크/과슈 재질 유지.

## 2026-10-28 동작 연출
- 사용자: "만세하는 느낌", "어깨에 망치 들고 있다가 내려치는 동작", "정면을 보는 느낌이 아닌".
- 규칙: 도구 동작은 실제 몸 쓰는 순서(준비 자세 → 예비동작 → 타격 → 복귀)로 설계하고, 단계별로 느리게(?slowswing) 캡처해 확인.
  정면 그림 한 장으로는 옆 동작이 어색하다 — 방향별 그림이 필요하면 일찍 말한다.

## 2026-10-28 매 프레임 값을 자기 자신에 누적하지 말 것
- 패턴: 애니메이션 값(scale.x)을 `abs(현재값) × 진행도`로 갱신 → 진행도 < 1인 동안 누적 축소되어 0에 갇힘(캐릭터 사라짐).
- 규칙: 프레임마다 바뀌는 변환은 저장해 둔 기준값에서 매번 새로 계산한다(base × factor). 이전 프레임 결과에 곱하지 않는다.
  검증 시 '그림이 바뀌지 않는 경로'(제자리 방향 전환 등)도 따로 재현해 본다.

- 영상→스프라이트: AI 영상의 한 구간을 그대로 쓰지 말고 (1) 실루엣 비교로 보행 주기를 찾아 정확히 한 주기만 자르고 (2) 깜빡임 같은 비주기 동작이 든 구간은 피한다 — 루프마다 같은 깜빡임이 반복되면 어색하다. 앵커 이미지는 투명 PNG 대신 단색 그린스크린에 합성해서 넣고, 키잉은 '배경색과의 거리'가 아니라 '초록 초과량'으로 해야 압축 노이즈에 강하다.
- 입력 버퍼처럼 입력 경로를 감싸는 변경을 할 때는, 원래 함수가 하던 부수효과(여기서는 `move()`가 ↑/↓에서 방향만 바꾸던 것)를 조건문 안으로 옮기면서 잃지 않았는지 확인한다. "왼쪽 부수고 → ↓ → 망치"가 측면으로 계속 휘두르던 회귀가 이렇게 생겼다. 체크: 좌우·위아래 각 방향으로 돌아서 치기를 한 번씩 해 본다.
- 브라우저 확인 중 사용자가 같은 Chrome 창에서 플레이하면 키 입력이 내 탭으로 들어간다(입력 없이 망치질 수가 오르면 이것을 먼저 의심).

- 판정이 입력 즉시 일어나는 게임에서 공격 애니메이션은 '준비 동작을 길게'가 아니라 '임팩트를 판정 순간에' 맞춘다. 준비 동작을 균등 시간으로 재생하면 결과(파편)가 먼저 나오고 동작이 빈 곳을 치며, 쿨다운보다 긴 애니메이션은 연타 시 처음만 반복된다. 무적 깜빡임 중엔 캐릭터가 안 보일 수 있으니 화면 확인 시 invuln을 끄고 본다.
- 애니메이션이 '안 보인다'는 보고는 먼저 재생 여부를 프레임 단위로 기록(dev 훅)해서 '재생 안 됨'과 '재생되지만 가려짐/너무 짧음'을 구분한다. 이번엔 재생은 됐고 깊이 정렬로 블록 뒤에 가려진 것이었다(첫 수정은 타이밍만 고쳐 헛다리).
- 배포 확인은 "파일이 올라갔다"(curl 200, 버전 일치)로 끝내지 말고 배포된 페이지에서 계산된 스타일과 화면을 로컬과 비교한다. Vite 빌드는 HTML의 인라인 `<style>` 뒤에 번들 CSS `<link>`를 넣어서, 개발 서버와 CSS 적용 순서가 반대가 됐다. 그래서 배포본에서만 옛 2D 스타일(Comic Sans)이 이겼다. 페이지 CSS는 JS에서 import해 순서를 고정한다.
